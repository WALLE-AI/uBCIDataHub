从发现数据，到开始研究

BCI DataHub 门户原型的资源组织与接入说明。

本文说明目标工作流，不代表真实数据、SDK、模型服务或审批服务已开放。

01 / 数据组织

目录按数据集、受试者、会话与模态组织。每一版本应关联采集说明、标签协议、质量报告和使用条件。具体格式根据数据模态及适用规范确定。

dataset-version/
  dataset_description.json
  participants.tsv
  sub-001/
    ses-001/
      eeg/
      events.tsv
  quality/
  CHANGELOG.md

以上为结构示意，不宣称覆盖全部 BIDS 要求。实际接入需按选定规范及版本校验。

02 / 可复现研究

  • 固定数据集版本，并记录纳入与排除规则。
  • 按研究问题选择跨被试或跨中心划分，避免同一受试者相关片段跨训练与测试集泄漏。
  • 记录预处理、标签映射、随机种子、模型版本和评价指标。
  • 基准工具须确认对当前模态与任务的支持范围。
# 研究记录示例，非可调用 SDK
dataset: stroke-mi
version: 5
split: subject-independent
preprocessing: recorded-in-protocol
seed: 42
metrics: defined-per-task

03 / 机构接入

准备机构类型、数据概况、模态、采集协议、可共享范围与合作意向。首轮沟通仅需元数据概述，无需在门户申请中上传原始信号或受试者信息。

访问方式

  • 开放资源：由有效资源链接与许可说明指导使用。
  • 申请访问：用途和范围审核后，获得对应权限。
  • 受控计算：在授权环境中执行任务，按约定导出结果。
  • 暂未开放：先查看开放说明或登记需求。

04 / 技术架构与能力边界

平台目标架构包含算力调度、数据供给、预训练与微调、评估基准和模型服务五层。权限、质量、版本、监测及审计贯穿各层。

05 / 原型资源说明

目录收录真实外部研究数据，详情中的“前往来源获取”可打开原始发布页；本门户尚未托管信号文件。申请不会提交到服务器。正式上线前需要接入目录、身份、授权、质量报告与审批服务，并验证其失败恢复行为。
